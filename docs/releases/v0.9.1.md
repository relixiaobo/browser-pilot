# Browser Pilot 0.9.1

Browser Pilot 0.9.1 makes the site knowledge shipped in 0.9.0 reachable. That
release put seven notes in the plugin archive and told Agents to copy them into
the state directory, without saying where they were — so every corpus stayed
empty and nothing reported it.

## Seeding resolves

`SKILL.md` now locates the shipped notes two ways: as the `sites/` directory
beside `SKILL.md`, next to `compatibility.json` and `references/`, which is how
the skill already directs Agents to its own files; and as
`${CLAUDE_PLUGIN_ROOT}/skills/browser-pilot/sites/` on a host that sets that
variable. An Agent that still cannot find it now says so once and carries on,
because the corpus grows from its own notes either way.

A test pins the instruction against the tree it resolves into, so the directory
it names cannot be renamed or dropped without failing.

## Deliveries respect their own schema

The result schema caps the `site` array at 32 entries while the store admits up
to 256 files, so a URL matching more than 32 notes produced a result the
protocol rejects. Delivery now trims to the cap and spends the last slot saying
how many matches were left out, rather than shortening the list silently.

## Upgrading

No protocol change. 0.9.1 speaks `1.4` exactly as 0.9.0 does; only the skill
text and the delivery bound moved.
