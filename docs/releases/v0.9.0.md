# Browser Pilot 0.9.0

Browser Pilot 0.9.0 adds site knowledge: durable notes about a specific website,
delivered on the observation an Agent was already making. They record what a page
cannot show — the traps and constraints that are otherwise rediscovered on every
task. Protocol `1.4` carries a new optional `site` field on observation results;
it is additive, and every existing command keeps its shape.

## Notes arrive with the observation

- Markdown files under the state directory, one per site, matched against the
  observed URL by `host` or `host/path-glob` patterns. `bp status` reports the
  directory as `paths.sites`.
- A matching file is inlined whole the first time an Agent sees that version and
  shrinks to name, summary, and path afterwards. The short form keeps the path, so
  an Agent whose context was compacted can read the file again.
- Delivery de-duplicates on the file's modification time rather than on anything
  written inside it, so an Agent repairing a note cannot forget to invalidate it,
  and one Agent's repair re-delivers to every other Agent.
- Reading the corpus never fails an observation. Knowledge is an aid, not a
  precondition, and a corpus that cannot be read simply produces no field.

## The corpus belongs to the user

There are no site-knowledge commands. Agents read and write these files with the
tools they already have, and so can the user, with any editor. Nothing in the
product writes to the directory: the store imports only read operations, tests
pin that installing and upgrading never reach user state, and shipped files are
copied in once, when the directory does not yet exist, so a file the user deleted
never returns.

Seven notes ship as a starting corpus, each written from a live session against
the site it describes: GitHub issue lists, Google search, Google Docs and Sheets,
Google Calendar, YouTube, npm package pages, and Stack Overflow.

## Observation guidance the seeds uncovered

Verifying those notes exposed behaviour worth stating for every site, now in
`SKILL.md`:

- An open picker can fill a whole snapshot on its own. At the default limit a
  GitHub label picker returned nothing but its own options, and `truncated` with
  `element_limit` was the only sign the page was missing.
- `bp read` can pick the wrong region and can return text that is not on screen.
  On an npm Versions tab it returned the README instead; on YouTube it returned
  hidden player text reading "You're signed out" on a signed-in page. Content
  must never be reported absent, nor session state reported, from a read alone.
- Some containers surface as a single control whose name is everything inside
  them, running past a thousand characters.

## Upgrading

The CLI now requests the newest protocol it supports rather than a fixed version.
A 0.9.0 CLI talking to an older Broker negotiates down and simply receives no
site field; an older CLI against a 0.9.0 Broker does the same. Skill and CLI move
together, as `compatibility.json` requires.
