# Browser Pilot 0.8.0

Browser Pilot 0.8.0 finishes making same-process frames a normal part of a page.
Every observation command now covers them: `bp read` includes their text and
`bp search` finds it, joining `bp snapshot`, `bp find`, and `bp locate`, which
already descended. This changes what `bp read` returns for a page that embeds
content in a frame, which is why it is a minor release. The CLI surface, the
private Broker protocol, and the Observation v1 element shape are unchanged.

## Page text and search reach frames

- `bp read` substitutes each same-origin frame's text in place of its iframe
  element, so content reads where the frame sits rather than appended after
  everything else.
- `bp search` walks the same frame tree, and a match reports coordinates that
  include its frame's offset, so they stay usable with `bp click --xy`.
- Both stop where a document becomes inaccessible, so cross-origin frames remain
  absent — the same boundary every other observation command draws.

## Why this mattered

A frame holding prose and no controls produced an empty snapshot, an empty read,
and zero search matches at once. An Agent received no signal that content
existed and would reasonably conclude the page was empty. `bp find` could
recover the text, but only for an Agent that had already guessed a selector, and
nothing in the observation suggested trying.

## Measurement

The capability benchmark's nested-frame scenario now carries host text after its
frame, and the browser test asserts frame content lands between the host's
leading and trailing text rather than merely appearing somewhere. An earlier
assertion anchored only on text above the frame and passed against a build that
appended frame text at the end, which reads a page out of order.
