# Browser Pilot 0.6.1

Browser Pilot 0.6.1 removes the Node.js prerequisite from managed Agent
installation on platforms that have an official native release. The CLI and
private Broker protocol remain compatible with v0.6.0.

## Native-first managed installation

- The Browser Pilot skill now reuses any installed CLI in its declared
  compatibility range, then installs the exact skill-tested native release
  when `bp` is absent or incompatible.
- Apple Silicon macOS, x64 Linux, and x64 Windows Agents can install `bp`
  directly from the matching GitHub Release without system Node.js or npm.
- npm remains a pinned fallback only for platforms without a native release;
  that fallback continues to require Node.js 22 or newer.
- Managed installation never follows mutable GitHub `latest` or npm `@latest`
  targets. Release metadata, the native tag, and the npm fallback version are
  generated together from the root package version.

## Installation integrity and ownership

- Native installers verify the release archive against its published SHA-256
  sidecar before extraction.
- Installations preserve the complete licensed release in a versioned
  directory and expose both `bp` and `browser-pilot` command entries.
- Installers refuse to replace unmanaged commands and do not silently edit
  shell startup files or the system `PATH`.
- Unsupported platforms return a dedicated exit code so an Agent can
  distinguish a valid npm fallback from download, checksum, extraction, or
  filesystem failures.

## Agent guidance

- The skill carries a grouped command table, so an Agent can discover a command
  without loading the full command reference.
- CLI installation and repair detail moves to `references/setup.md`. The
  `bp --version` compatibility gate keeps it reachable, so no path skips the
  installation contract.
- The skill states the tab-ownership contract: announce Browser Pilot-created
  tabs once, and keep closing user-initiated.
- Connection guidance is unchanged. The Allow reminder, the single pending
  connection request, and the prohibition on looping `bp connect` remain in the
  skill body.

## Release validation

- The Agent plugin packages both POSIX and Windows installers and declares its
  npm CLI peer dependency as optional for native installations.
- Unit and distribution tests cover version synchronization, archive checksum
  validation, command conflicts, versioned installation, and `PATH` reporting.
- Every release runner installs and executes its freshly packaged native
  archive before the artifacts can be published.
