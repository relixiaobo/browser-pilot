# Browser Pilot 0.9.3

Browser Pilot 0.9.3 documents what happens when a newer executable is installed
while the previous one's service is still running. Nothing in the product
changed; the guidance ships because the skill travels in the plugin package, so
a documentation-only change still needs a release to reach anyone.

## Upgrading while the service is running

`references/setup.md` now explains a state that reads as a contradiction:
`bp --version` reporting the new version while `bp status` still reports the old
one under `service.version`. The service is a separate process owned by the
executable that started it, so browser work keeps using the old one until it
stops.

It also explains why `bp disconnect` can report success without stopping
anything. Shutdown requires the requesting executable's version *and* identity to
match the running service's; when they differ the call releases state and
returns quietly, so one installation can never terminate another's service. The
documented procedure is to disconnect with the executable matching
`service.version` — a native installation keeps every version it has installed —
then install, then confirm the versions agree.

The guidance ends by ruling out the obvious workaround: do not signal the
service process. A refused disconnect is the ownership check working.

## Upgrading

No protocol change; 0.9.3 speaks `1.4` as 0.9.2 does.
