# Browser Pilot 0.9.5

Browser Pilot 0.9.5 strengthens the shipped Site Knowledge path without changing
the CLI or protocol. It gives the seven bundled site notes an upstream
freshness loop, records repeatable evidence for the Agent doctrine around those
notes, and fixes the cross-platform release gate added by that work.

## Shipped notes now expire unless reverified

Every note under `plugin/skills/browser-pilot/sites/` is bound to a repository
verification record containing its exact SHA-256, `updated` date, verification
date, and evidence reference. Ordinary CI checks coverage and byte identity. A
weekly workflow warns once a record reaches 75 days, and the release workflow
blocks at 90 days.

Changing a shipped note therefore requires a matching live verification rather
than a date-only refresh. A note that cannot be safely reverified must be
removed or held back from the release.

This ledger covers only repository originals. Browser Pilot does not inspect,
diff, fingerprint, or upload a user's `~/.browser-pilot/sites` corpus.

## Upstream reports require explicit, redacted consent

The managed skill now distinguishes a local-only correction from an error that
also exists in the current shipped original. For a shipped defect, the Agent
may offer the repository's stale-note issue form, but it must show a minimal
redacted draft and receive explicit approval before creating anything public.

Credentials, account identifiers, private or signed URLs, private page content,
screenshots, local paths, and the user's site-knowledge files stay out of the
report.

## Doctrine checks are reproducible

The repository now carries deterministic read, repair, and write fixtures for
the Site Knowledge doctrine, together with recorded directional and durable
checkpoint baselines. These checks distinguish reading a delivered note,
repairing a contradicted note, merely working around it, and writing a durable
note after discovering a reusable hidden constraint.

## Seed hashes are stable on Windows

The first post-implementation CI run exposed a checkout-specific false failure:
Windows converted seed Markdown from LF to CRLF before the byte-bound hash
check. Git attributes now keep shipped seed bytes on LF on every platform, with
a regression assertion and a successful Windows CI run.

## Upgrading

No protocol change; 0.9.5 speaks `1.4` as 0.9.4 does. Runtime browser behavior
is unchanged. Upgrade to 0.9.5 to receive the updated managed skill and the
release artifacts carrying its synchronized compatibility metadata.
