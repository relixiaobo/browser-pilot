# Browser Pilot 0.6.2

Browser Pilot 0.6.2 is a maintenance release. It restructures the Agent skill
for faster command discovery, moves continuous integration onto supported
GitHub Actions runtimes, and closes a release-pipeline gap that let a
prerelease advance the stable managed skill branch. The CLI and private Broker
protocol remain compatible with v0.6.0 and v0.6.1.

## Agent guidance

- The skill carries a grouped command table, so an Agent can discover a command
  without loading the full command reference.
- CLI installation and repair detail moves to `references/setup.md`. The
  `bp --version` compatibility gate keeps it reachable, so no path skips the
  installation contract.
- The skill states the tab-ownership contract: announce Browser Pilot-created
  tabs once, and keep closing user-initiated.
- Connection guidance is unchanged. The Allow reminder, the single pending
  connection request, and the prohibition on looping `bp connect` remain in the
  skill body.

## Release pipeline

- A prerelease no longer advances the `skill-stable` branch. That branch is the
  stable channel for managed skill installations, and advancing it from a
  release candidate would have moved every managed installation onto an
  untested skill. The gate matches how release publication already classifies a
  prerelease.
- Release publication fetches enough history before fast-forwarding
  `skill-stable`.

## Continuous integration

- `actions/checkout`, `actions/setup-node`, `actions/upload-artifact`, and
  `actions/download-artifact` move to maintained majors on the Node.js 24
  action runtime. Every workflow input in use was checked against each
  intervening major.
- Windows shell text encoding is pinned in both directions across
  powershell.exe, cmd.exe, pwsh, and git-bash. Agent-authored non-ASCII text
  survives the shell boundary intact, inbound as a command argument and
  outbound as JSON on stdout.
- The isolated Chrome test fixture allows a realistic startup budget and now
  reports Chrome's exit status, elapsed time, and captured stderr when startup
  fails, instead of discarding the evidence.
